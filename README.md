# bendsidecar — Bend 2 как sidecar для Go

Гоняет программы на Bend 2 из Go как изолированные процессы: аргументы на вход, байты на выход, падение — код возврата, а не смерть хоста.

## Зачем именно так

Bend 2 компилирует программу целиком в один C-файл и запускает её как программу, а не как библиотеку:

- вызвать функцию из чужого процесса нельзя — есть только `main`, argv и event loop;
- каждый прогон **течёт**: 100 вызовов в одном процессе = +400 MB RSS, рантайм не отдаёт стеки;
- падение внутри Bend — `abort()`, то есть смерть всего процесса-хоста;
- `ulimit -v` бесполезен: Bend резервирует терабайты адресного пространства.

Поэтому единственная честная форма — один процесс на вызов. Эта библиотека и есть обвязка: сборка с кешем, запуск, таймаут, изоляция, разбор ответа.

## Установка

```sh
go get github.com/Gwushor/bendsidecar
```

Нужен компилятор Bend 2 на PATH: `curl -fsSL https://bend-lang.com/install.sh | sh`.

## Использование

```go
p, err := bendsidecar.Open(ctx, "risk.bend",
    bendsidecar.Threads(4),
    bendsidecar.Timeout(2*time.Second),
    bendsidecar.Validate(func(out []byte) error {   // провод не доказан, проверяй сам
        return nil
    }),
)
if err != nil { return err }

res, err := p.Call(ctx, "1500", "300")   // argv для самой программы
if err != nil {
    if bendsidecar.Is(err, bendsidecar.KindTimeout) { /* ... */ }
    return err
}
n, err := bendsidecar.FirstInt(res.Stdout)
```

Большие данные — вторым транспортом, файлами:

```go
out, err := p.CallFiles(ctx, payload)   // payload пишется в in.bin, ответ читается из out.bin
```

Дочерний процесс запускается в свежем каталоге, где уже лежит `in.bin`, а ответ он оставляет в `out.bin`; `in.bin` и `out.bin` передаются ему первыми двумя аргументами. Пустой/отсутствующий `out.bin` — это `KindBadInput`, а не «пустой ответ».

Два контракта:

- **argv → stdout**: программа читает `IO.args()` и пишет `IO.print`. Потолок — `ARG_MAX` (~2 МБ). `IO.args()` включает `argv[0]`, то есть без аргументов длина 1, с тремя — 4 (проверено тестом).
- **файлы**: `File.open` / `File.read` / `File.write` / `File.size` / `File.close` есть в Base, открывать через `IO.pass(File, File.open(bendsidecar.InFile, "rb"))`. Размер входа не ограничен.

Чего в Base нет — добавляется самой программой: `def x() -> IO(...): import "./effs/x.c"` плюс `.js`-двойник — это foreign effect. Пакеты Bend тоже есть (`--publish` / `link`). Помни, что обещания ABI у foreign effects нет: гайд Bend прямо велит пересобирать их с каждым обновлением компилятора.

## Что делает обвязка

- **Сборка с кешем**: ключ — sha256 содержимого `.bend` плюс версия компилятора, бинарь в `~/.cache/bendsidecar/`. Правка исходника или апгрейд `bend` пересобирает, повторные `Open` дешёвые.
- **Таймаут и убийство группы процессов**: рантайм поднимает пул потоков, поэтому убивается вся группа (`Setpgid` + `kill -pid`), а не один процесс.
- **Изоляция ошибок**: сигнал → `KindCrash` (это `abort()`), ненулевой код → `KindExit`, таймаут → `KindTimeout`, ошибка компиляции → `KindBuild` с хвостом stderr.
- **Пустое окружение**: ребёнок не наследует env родителя, поэтому случайно утёкший секрет в sidecar не попадает. `Threads` передаётся аргументами `+RTS --threads N -RTS`.
- **Ограниченный stderr**: последние 8 KB, чтобы болтливый ребёнок не съел память хоста.
- **`Verdict`**: `bend --verdict` как гейт в CI. Требует ядро BendTT (Lean v4.34.0 через elan или `$BENDTT`), без него команда падает — это отдельный опциональный шаг, не горячий путь.

## Чего библиотека не гарантирует

`LAWS.bend` гарантирует то, что смоделировал чекер. C-граница, полученный argv и напечатанные байты в модель не входят. Поэтому выход проверяется на стороне Go (`Validate`) — «оно же доказано» не аргумент.

И не передавай секреты аргументами: они видны в `/proc` всем локальным пользователям.
